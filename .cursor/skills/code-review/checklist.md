# 代码审查清单

作扫描列表使用；并非每项都适用于每次改动。

## 正确性与逻辑

- [ ] 主流程符合需求
- [ ] 边界情况：null/空、越界、重复提交、并发
- [ ] 错误路径有处理；失败不被静默吞掉
- [ ] 状态一致：无陈旧 UI、重复提交、半更新状态
- [ ] 重试/重复事件场景考虑幂等
- [ ] 差一错误、时区、编码、精度/舍入

## 安全

- [ ] 代码、日志、提交中无密钥、Token、敏感个人信息
- [ ] 信任边界上的输入有校验
- [ ] 敏感操作有权限控制（不只鉴权）
- [ ] 注入风险：SQL、命令、路径穿越、XSS 等
- [ ] 未引入已知高风险依赖或用法

## API 与契约

- [ ] 对外 API / 数据结构变更向后兼容或已版本化
- [ ] Breaking change 有文档且调用方已更新
- [ ] 序列化与服务端/客户端一致（字段名、可空性）

## 架构与设计

- [ ] 职责在正确分层（UI / 领域 / 数据）
- [ ] 无不当耦合或循环依赖
- [ ] 抽象有必要，非过度设计
- [ ] 改动规模合理；超大 PR 建议拆分

## 可读性与可维护性

- [ ] 命名能表达意图
- [ ] 函数职责单一；嵌套不过深
- [ ] 无死代码、调试输出、大段注释掉的代码
- [ ] 魔法数字/字符串在必要时提取常量
- [ ] 注释解释「为什么」，而非复述「做什么」

## 性能与资源

- [ ] 热路径无明显的 N+1、无界循环、大对象频繁分配
- [ ] 缓存有理由；失效策略正确
- [ ] 连接、文件、监听器已关闭或绑定生命周期

## 并发与异步

- [ ] 共享状态有同步或使用不可变结构
- [ ] 必要时支持取消/超时
- [ ] 清理与新工作无竞态（如登出未完成就跳转）

## 测试

- [ ] 行为变更配有测试，或说明为何不测
- [ ] 测试断言行为而非实现细节
- [ ] 关键路径的失败场景有覆盖

## 可观测性与运维

- [ ] 错误日志有足够上下文，不含敏感信息
- [ ] 影响核心链路时考虑指标/告警

## 文档与配置

- [ ] 需要时更新 README、迁移说明、配置示例
- [ ] Feature flag / 环境变量有说明
